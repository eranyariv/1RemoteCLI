1RemoteCLI

Answer your terminal from any device with a browser.

What this is

You start a long job (a refactor, a build, an AI coding agent) and walk away. Twenty minutes later it is sitting on “Do you want me to apply these changes? (y/n)”, and has been for nineteen of them.

1RemoteCLI attaches a browser to a terminal session already running on your Windows machine. Read the output, answer the prompt, press Esc to back out of a menu, walk away again. It buzzes when a session needs you, and the same page works just as well from a tablet or a second desktop.

Put 1remote in front of whatever you were going to run:

1remote claude

It behaves exactly like running the program directly: same colours, same keystrokes, same Esc, same exit code. The difference is that it is now also visible from somewhere else.

What it is not

  • Not a remote desktop. It shares one terminal session, not your screen and not your machine.
  • Not an inbound connection. Both your PC and the device you are watching from dial out to a relay, so nothing on your machine has to be reachable from the internet and no ports are opened.
  • Nothing to install on the other device. The remote side is a web page. On a phone or tablet you can add it to the home screen; on a desktop you can install it as an app or just leave it in a tab.

Before you point it at a machine that matters: anyone holding a signed-in device can type into your shared sessions. Read Security first.

Installing on Windows

You need

Windows Windows 10 version 2004 (build 19041) or newer, which is where ConPTY became reliable.
An account A Microsoft account, personal or work/school, that has been added to this hub’s allowlist. If it has not been, sign-in will succeed and then the hub will refuse you, which is a confusing five minutes. Ask whoever runs the hub.
Repo access The project is private for now, so you also need to have been given read access to eranyariv/1RemoteCLI. The installer downloads from it, and every GitHub link on this page needs it too. Ask whoever sent you here.
Something to watch from Anything with a reasonably current browser: a phone, a tablet, a laptop, a second desktop. On iOS you want 16.4 or newer, which is where web push arrived; anything older still works, it just will not buzz. There is nothing to install on it.

No admin rights are needed. Everything installs under your own user account.

  1. Install it

    In PowerShell:

    $env:GITHUB_TOKEN = gh auth token
$headers = @{ Authorization = "Bearer $env:GITHUB_TOKEN" }
irm https://raw.githubusercontent.com/eranyariv/1RemoteCLI/main/scripts/install.ps1 -Headers $headers | iex

    The token appears twice on purpose, and the two uses are not interchangeable: the header is what fetches the script, because raw.githubusercontent.com reads the request header and nothing else, and the variable is what the script then uses to read the release. This is only necessary while the project is private. gh auth token assumes the GitHub CLI; a fine-grained token with read access to the repository does just as well.

    That picks the build for your architecture, checks it against the SHA-256 published with the release, puts it in %LOCALAPPDATA%\Programs\1RemoteCLI, registers it to start when you sign in, and adds it to your PATH.

    Then open a new terminal, because the PATH change only reaches terminals opened after it, and check: 

    1remote --version

  2. Sign in

    1remote login

    A browser opens. Sign in with the account that is on the allowlist. The token is cached under your Windows user and encrypted with DPAPI, so another account on the same PC cannot read it and it cannot be copied to another machine and reused. You will not have to do this again.

  3. Start the agent

    It will start by itself at every sign-in from now on. To start it now without logging out: 

    1remote agent

    You get a tray icon. That is the agent: one per machine, holding the connection and the list of live sessions. Sessions are not shared unless it is running.

  4. Share a session

    1remote claude
1remote pwsh
1remote --name "nightly build" -- pwsh -File .\build.ps1

    If you start your tool from a desktop shortcut instead of by typing its name, there is no command line to put 1remote in front of. Right-click the tray icon, choose Settings…, and use Wrap a desktop shortcut… to make a copy that shares its session.

  5. Open it on your other device

    Go to this same address in a browser on whatever you want to watch from, phone, tablet or another computer, and sign in with the same account. Your machine is listed, with its sessions under it. Open one and you are attached: you get the current screen immediately, not a blank terminal waiting for the next byte.

    Then install it and allow notifications. On a phone or tablet that is “Add to Home Screen”; on a desktop browser it is the install button in the address bar. Without notifications you have to remember to check, which defeats the point.

“Windows protected your PC”

The executable is not code-signed, so SmartScreen will stop you the first time. That is expected, and it is not a false positive in the interesting sense: the binary genuinely has no publisher identity attached to it.

Check it is the file that was published before you get past the warning:

Get-FileHash .\1remote.exe -Algorithm SHA256

Compare that with the SHA-256 in SHA256SUMS.txt on the release. If it matches, click More info → Run anyway. If you would rather not trust a hash from the same place as the binary, build it yourself: the publish script produces exactly what the release contains, and prints the hash.

Uninstalling

1remote uninstall    # stop starting at sign-in, come off your PATH
1remote logout       # forget the cached sign-in

Then delete the two folders it used:

Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Programs\1RemoteCLI"
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\1RemoteCLI"

uninstall deliberately leaves the executable where you put it; it does not delete files it did not create. Quit the tray agent first, or the second command will refuse to remove a file that is in use.

On the device you were watching from, remove the installed app or home screen icon as you would any other. Nothing of yours is left on the server: it relays traffic and stores no terminal content.

Telling us it is broken

Feedback is wanted, including the blunt kind. Two ways, and the first is easier if you are holding a phone:

Email eran@yariv.org. The Send feedback link in the agent’s settings window and in the web app’s footer opens this with the version already filled in.
GitHub Open an issue, best for anything reproducible.

What helps most, in order:

  1. The version, from 1remote --version.
  2. What you expected, and what happened instead.
  3. The log, from %LOCALAPPDATA%\1RemoteCLI\logs, or via Open logs in the settings window. It is safe to attach: it records how much data moved and when, never what was on your screen. Not the output, not what you typed, not even the session’s name.

If something is not working at all, start with Troubleshooting.
